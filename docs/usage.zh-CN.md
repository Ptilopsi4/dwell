# 使用指南

[English](usage.md) | 简体中文 | [README](../README.zh-CN.md)

通过飞书、Telegram 或网页面板使用 dwell。机器人设置见[部署指南](deployment.zh-CN.md#bot-配置)，模型连接与用户白名单见[配置](configuration.zh-CN.md)。

## 命令

机器人命令需要用户授权。Telegram `/whoami` 可在授权前查询 ID；未启用群内明确发给机器人的命令会收到固定接入提示，包含用户和群 ID，不会启动任务。

| 命令 | 作用 | 谁能用 |
|---|---|---|
| `/new` | 切换新的默认任务线，保留原任务线与历史 | 任务线所有者、管理员 |
| `/newgoal` | 开始新工作目标，保留历史、旧记录与预算 | 任务线所有者、管理员 |
| `/cancel` | 中止当前任务 | 任务线所有者、管理员 |
| `/status` | 列出运行中的任务 | 管理员 |
| `/approve [分钟]` | 为自己打开危险命令审批窗口，并续跑待审命令 | 显式授权用户；仅有群授权的成员需管理员审批 |
| `/deny` | 关闭自己的审批窗口并拒绝待审命令；管理员关闭该任务线所有窗口 | 所有人 |
| `/allow <用户> [admin]` | 解除封禁并授予全局成员或管理员权限 | 管理员 |
| `/disallow <用户>` | 封禁用户，优先于群授权；最后一位管理员不能移除 | 管理员 |
| `/allowgroup`（Telegram） | 开放当前群成员使用，自动识别群 ID | 管理员 |
| `/disallowgroup`（Telegram） | 停用当前群，无需填写 ID | 管理员 |
| `/allowchat [群ID]`（Telegram） | 启用群，仅允许显式授权用户；群内可省略 ID | 管理员 |
| `/disallowchat [群ID]`（Telegram） | 关闭群输入与后续投递，保留既有工作 | 管理员 |
| `/chats`（Telegram） | 列出当前机器人已启用的群及开放模式 | 管理员 |
| `/whoami` | 显示自己的平台用户 ID | 所有人 |
| `/help` | 显示使用说明 | 所有人 |
| `/start`（Telegram） | 显示开始使用的指引，不调用模型 | 已授权用户 |
| `/ask <任务>`（Telegram） | 提交文字或附件；空 `/ask` 显示用法 | 已授权用户 |

命令按已知列表精确匹配。审批窗口默认 10 分钟，`/approve` 接受 1 至 120 分钟。没有待审命令时，`/deny` 不会发起新一轮执行。飞书用户可用 `@某人` 或 `ou_...` ID；Telegram 必须用 `tg:<数字用户 ID>`，用户名不能用作权限 ID。

`/newgoal` 要求当前会话没有运行中或排队输入，需要时先用 `/cancel`。预算耗尽后，可解除当前目标绑定，再发送新目标。旧工作记录、预算、证据和审批继续保留，旧后台任务与托管进程回报仍归属创建它们的工作。此操作不清空聊天历史。预算、后台任务与验证记录见[代理运行机制](agent.zh-CN.md)。

## 审批危险命令

bash 命令命中 `rm -rf`、远程 `ssh`/`scp`/`rsync`、带数据或非 GET 方法的 `curl`、`wget --post`、全局装包（`npm install -g`、`apt install`、`pip install`）、`docker`、`systemctl` 或 `crontab` 时会暂停等待审批。`sudo` 和访问状态文件的命令直接拒绝。这些检查属于[安全边界](security.zh-CN.md)的一部分。

显式授权用户触发审批请求后，可发送 `/approve`，窗口只放行本人在该任务线中的危险命令。原触发者、任务线所有者和管理员也可点击原卡片/按钮审批。对他人的请求发送 `/approve` 只会打开自己的窗口，他人的请求继续待审。Telegram 中仅有群授权的用户需 dwell 管理员点击原审批卡批准，不能开窗口或批准请求，但可用 `/deny` 拒绝自己的请求。命令决定会在原卡片仍可用时更新其状态。面板任务只向面板操作者私聊发送审批请求，不会发到群里。

审批决定先保存，再提交续跑。状态写入失败时，待审请求和已有窗口保持原样。已保存决定会在启动时与退避重试中使用同一投递 ID；后台续跑经回报任务送回。重放保持原到期时间，不会延长已过期窗口。这些恢复规则不保证外部副作用恰好执行一次，也不保证机器断电后的持久性。

旧飞书审批卡缺少持久化请求 ID 时不能授权续跑。请重新请求审批，或由操作者处理任务。

## 飞书

### 会话路由

| 消息 | 路由到 |
|---|---|
| 私聊 | 你的个人任务线，连续对话 |
| 群里 @机器人 | 你在该群的个人任务线，每人独立运行 |
| 回复任务线内的消息，包括成员给机器人的输入、审批卡或通知 | 该任务线，无需 @机器人 |
| 话题群里的消息 | 话题共享任务线，无需 @机器人 |

同群所有任务线共享 `work/<chat_id>/`，遵守[工作区写入规则](agent.zh-CN.md)。运行中发送的消息会作为补充输入插入当前任务。回复无法追溯到任务线时，例如超过 10,000 条消息映射范围，私聊与 @机器人消息会新建任务线并提示。

飞书 `/new` 切换新的默认任务线。原任务线、工作记录、预算和消息锚点保留，回复旧消息或使用面板可继续旧线；已有后台工作与共享工作目录不受影响。旧线达到 64 项工作记录上限后，也可用此方式开始新线。面板的「清空上下文」仍只清上下文。同群成员共享文件，也能通过回复加入他人任务线；敏感内容请用私聊。

## Telegram

### 开始对话

先私聊机器人并发送 `/whoami`，获取 `tg:<数字用户 ID>`，未授权时也可使用。请管理员用 `/allow tg:123456789 [admin]` 添加该 ID，或通过可信面板管理。首次安装的环境变量播种见[配置](configuration.zh-CN.md)，已有 `state/users.json` 时以文件为准。

授权用户可发送 `/start` 或 `/help` 查看说明。`/ask` 不带文字时显示提交方式；附带图片或文件时仍会提交该附件。这些引导回复不调用模型。Telegram 的 `/` 提示需要通过 BotFather 或 `setMyCommands` 注册命令列表；启动 dwell 不会注册或覆盖机器人菜单。菜单可见不代表获得执行权限。

私聊接受显式授权用户的文本、图片与文件。群必须先启用：逐人授权模式要求发送者已有全局权限，群成员模式允许在该群发消息的真实用户使用，但封禁用户仍被拒绝。保持群隐私模式开启，使用 `/ask@your_bot 总结这段内容` 等带机器人后缀的命令，或实际回复这个机器人的消息。单独 `@your_bot` 不会发起任务。群尚未启用时，发送 `/whoami@your_bot` 也能查询群 ID；接入提示不会创建会话、下载附件或调用模型。频道、以群/频道身份发送的消息和其他机器人的消息会被忽略。

dwell 管理员在目标群发送 `/allowgroup@your_bot`，或点击「允许本群成员使用」，即可开放群成员。群 ID 直接取自这条消息，私聊误用会提示到目标群操作。简写 `/allowgroup` 只有在 Telegram 实际投递时才生效；保持隐私模式时请使用完整命令，或回复机器人发送。`/allowchat@your_bot` 则切回逐人授权模式，原有私聊形式仍接受负数群 ID，例如 `/allowchat -1001234567890`。历史群记录保持原模式，显式操作后才改变。`/chats` 显示各群当前模式。

群授权不授予私聊或管理权限，也不会把成员写入全局名单。危险命令遵守[管理员审批规则](#审批危险命令)，已有全局成员保留原审批规则。`/disallow tg:123456789` 会封禁该用户，群成员开放不能绕过；`/allow` 解除封禁并授予全局权限。

`/disallowgroup` 停用当前群，`/disallowchat` 也支持显式 ID。停用后拒绝新群输入与后续投递，已经发出的网络操作无法撤回。定时任务、后台子代理、托管进程和审批续跑在启动新工作或返回结果前，会按原始群复查创建者的当前权限；封禁创建者或撤销其群授权后，拒绝这些后续操作。既有工作、运行中的子代理和进程、日志与历史保留，沿用原取消方式。dwell 不跟踪实时群成员状态，也不会因成员离群自动停止工作。命令和按钮每次检查当前 dwell 角色，Telegram 群管理员不会自动获得此权限；旧控制请求重投也不会撤销后来的策略变更。

### 会话路由与命令

| 消息 | 路由到 |
|---|---|
| 私聊消息 | 你当前的个人任务线 |
| 群成员模式的普通群或论坛话题里 `/ask@your_bot 内容` | 你在该机器人、群和话题中的当前任务线，使用个人工作目录 |
| 逐人授权模式的普通群里 `/ask@your_bot 内容` | 你在该群的当前任务线，使用群共享工作目录 |
| 逐人授权模式的论坛话题里 `/ask@your_bot 内容` | 该话题的共享任务线与群工作目录 |
| 回复自己独立任务线中带已知锚点的机器人消息 | 该任务线，包括 `/new` 后保留的旧线 |
| 群成员模式中回复他人任务线或历史共享线 | 你自己的当前任务线，并提示已重定向 |
| 在既有逐人授权共享线中回复带已知锚点的机器人消息 | 该消息所属任务线 |
| 回复已查不到锚点的机器人消息 | 你当前的任务线，并提示降级路由 |

群成员模式按发送者分开路由与工作目录，论坛话题内也逐人独立。任务线建立后保留这一操作者范围，不随后续群模式变更而改变。运行期间收到的输入排队到下一轮执行，面板输入与后台回报也一样。既有逐人授权共享线保留原路由、共享目录与运行中插话行为。所有任务线遵守[工作区写入规则](agent.zh-CN.md)。独立目录不构成租户之间的硬隔离，读取权限等限制见[安全边界](security.zh-CN.md#准入与互信域)。

Telegram `/new` 建立新的默认会话，保留旧线及其操作者范围；新的独立任务线复用本人的工作目录，回复自己的旧消息或使用面板仍可访问旧线。群内命令使用机器人后缀，例如 `/cancel@your_bot`，也可以回复这个机器人的消息发送。危险命令使用内联审批按钮，遵守上方的[审批权限](#审批危险命令)。

### 回复更新与格式

附件下载或视觉处理期间，会尝试显示 Telegram「正在输入」状态，不调用模型生成进度。正式消息优先，预处理结束、取消或停机后停止刷新；客户端可能短暂保留最后一次状态。活动提示失败不会阻止任务继续。

机器人会在处理中回复上逐步更新正文，以及最近观察到的六项工具调用。每行显示文件名或站点等有长度限制的操作摘要、状态，以及回执提供的耗时。命令原文、原始输出、诊断文本和模型私有思考不会进入此展示区。私聊按 1 秒、群聊按 3 秒聚合更新，同时遵守 Telegram 限流。短回复可能在中间更新出现前就已完成。

完成、等待后台任务、待验收、中止或失败时，预览替换为确定的最终回复，并保留简短执行记录。Markdown 转换为 Telegram 文本实体，支持粗体、斜体、删除线、链接、行内代码和代码块。原始 HTML 按文字显示；图片语法转成文字链接，不自动上传远程媒体。普通文字中的 XML 和数字字符引用会解码，`&copy;` 等其他命名引用保留原文。

中间预览限制在一条消息内。最终全文在格式转换后拆分，每段重新计算格式实体位置。中间编辑失败会停止预览，仍尝试投递最终结果。并入同一轮执行的输入共用最终回复。发送响应丢失仍可能使投递结果不确定，恢复记录不保证出站消息或工具副作用恰好一次。持久化输入与恢复规则见[代理运行机制](agent.zh-CN.md)，webhook 和轮询故障见[部署指南](deployment.zh-CN.md#bot-配置)。

## 图片与文件

- 图片保存在工作目录 `uploads/`，由配置的视觉连接生成文字描述后交给主模型。视觉关闭或缺少密钥时只存图、不识别。
- 文件保存在 `uploads/`，模型可读取，上传后仍可修改。
- Windows 当前只支持文字，不接收附件。目录身份、独占写入等上传保护机制见[安全边界](security.zh-CN.md#文件工具与上传)。
- 视觉可复用主连接，也可使用单独的受支持 API 连接，见[配置](configuration.zh-CN.md)。显式视觉模型不支持图片时启动失败。每张图片请求限时 60 秒；失败时保留已保存图片并报告识别失败。
- 飞书群内不 @机器人发送的图片不会自动进入上下文，提问后模型可用 `dwell.lark.image` 按需回看。Telegram 图片需来自已接纳的私聊消息、带机器人后缀的群命令/图片说明，或对这个机器人的回复。
- 表情包不支持识别，音视频暂不支持。

Telegram 图片/文件下载上限为 20 MiB。`dwell.send` 发送当前会话工作目录内的文件：支持的图片（`png`、`jpeg`、`gif`、`webp`）不超过 10 MiB 时作为图片发送，更大的图片和其他文件不超过 30 MiB 时作为文档发送；空文件会被拒绝。面板任务在面板提供下载。旧名称 `dwell.lark.send` 仍仅供飞书使用；飞书历史与识图工具也仅供飞书使用，Telegram 不提供任意聊天历史查询。

模型面向的内置提示词与工具描述为英文，模型按用户语言回复。

## 网页面板

在可信工作机打开 `http://<host>:<DWELL_PANEL_PORT>/`。面板没有内置鉴权，请放在可信网络内，并遵守[安全边界](security.zh-CN.md)与[面板网络设置](deployment.zh-CN.md#panel-与网络)，包括本机来源限制。

- 侧栏按「我的任务 / 私聊 / 群聊 / 已归档」分组，实时显示对话记录，包含流式文本、工具调用和可折叠的思考过程。
- 通过回形针、粘贴或拖入附加图片与文件。图片经视觉描述后进入上下文；飞书/Telegram 会话里的附件先转发到原聊天。
- 工具行可下载 `dwell.send`、`dwell.lark.send` 或 `write` 产出的文件。下载限当前会话工作目录内、最多 30 MiB，强制附件下载，不内联执行。文件发送和面板附件转发共用受保护的工作区读取。
- 状态点反映面板实时通道与机器人连接：绿为正常，黄为连接中/重连中，红为断开。铃铛显示最近运行告警及未读数；时钟列出全部会话的活跃定时任务，可在此取消。
- 后台子会话展示在父会话下，可打开对话记录，也可通过会话菜单中止本轮执行。
- 可新建面板任务、重命名、归档、清空上下文、中止、审批命令和管理用户。会话菜单中的「开启新目标」与 `/newgoal` 行为相同。
- 从会话菜单或待验收通知打开「工作记录与验收」，核对目标、验收标准、产物范围、检查记录和交付说明后确认验收。验收失败会保留错误提示与刷新入口；文件变化后需重新验证。
- 向飞书/Telegram 会话发消息时，原聊天先显示「From admin」，再由机器人回复，群成员都可见。在面板中止或清空该会话，也会通知原聊天。
- 面板任务可开启机器人通知，完成、失败或需审批时，经操作者配置的平台私聊通知。回复通知即可从该平台继续任务。

验收前请检查标准与证据。`ready_for_review` 表示请求评审，操作者验收是单独动作。验证记录与验收行为见[代理运行机制](agent.zh-CN.md)，运行告警见[部署指南](deployment.zh-CN.md#运行告警)。
