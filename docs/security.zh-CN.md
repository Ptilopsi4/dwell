# 安全边界

[English](security.md) | 简体中文 | [README](../README.zh-CN.md)

各层从硬到软依次为容器/系统隔离、bash 沙箱（内核强制的挂载命名空间）、凭证擦除、文件工具路径检查、面板请求准入和危险命令正则。进程应以非 root 用户运行；Dockerfile 已创建 `dwell` 用户。部署隔离是硬边界。

## 准入与互信域

全局角色使用飞书 `ou_...` ID 和 Telegram `tg:<数字用户 ID>` 身份。Telegram 私聊要求显式角色，已启用的群可采用逐人授权模式，同样要求全局角色；也可采用群成员模式，允许在该群发消息的真实用户使用。持久封禁优先于这两类授权。群授权不创建全局角色，也不授予私聊或管理权限。仅有群授权的用户执行危险命令时，需 dwell 管理员点击原审批卡批准；已有全局成员保留原审批权限。未授权用户可以用 Telegram `/whoami` 查询自己的 ID，但不能提交任务。持久策略见[配置](configuration.zh-CN.md)，聊天命令见[使用指南](usage.zh-CN.md)。

飞书群与 Telegram 既有逐人授权任务线共享群工作目录，成员可通过回复加入他人的任务线。Telegram 群成员模式按机器人、群、话题、发送者分别建立路由和工作目录，回复他人任务线或历史共享线会回到自己的线。独立任务线在群模式变更或 `/new` 后保留操作者范围，`/new` 复用本人的目录。群消息与机器人回复仍对群成员可见，可信面板也能访问全部会话。

独立任务线及其后台子代理的文件工具只能读取、列出本人工作目录内的路径，检查按解析后的真实路径进行。群模式变更或重启后仍保留此限制，既有逐人授权线与其他共享线保留原读取策略。独立路由和目录不构成租户之间的硬隔离。bash 隔离取决于沙箱，临时目录共享，网络访问不受隔离。接纳互不信任的工作负载前，需配置相应的主机或容器边界。不应出现在群里的内容请用私聊。

新的定时触发、后台输入与回报、托管进程启动与回报，以及审批续跑，会按持久化创建者和原始群复查当前权限。撤权不会杀掉已运行的子代理或进程、撤回已发出的外部操作，也不会删除文件与历史。dwell 不查询实时 Telegram 成员状态，因此离群本身不会撤权或停止既有工作。

## 凭证

模型密钥（包括主模型、视觉配置中自定义的 `apiKeyEnv` 名称）、飞书凭证、Telegram 令牌和白名单读入内存后，会从进程环境中删除。Linux 下还会把启动时原始环境区（`/proc/<pid>/environ`）中的密钥值覆写为 0 并自检；擦除失败则拒绝启动。续跑任务在擦除完成后才恢复调度，bash 中的 `printenv` 和 `cat /proc/$PPID/environ` 都拿不到这些值。Telegram 请求错误会省略含令牌的 URL。

服务器探针 [test/probe-scrub.ts](../test/probe-scrub.ts) 检查凭证擦除，运行方法见文件头注释。

`GH_TOKEN` 是例外：`gh` 与 `git` 从环境变量读取凭证，因此 bash 仍能读取它。应按已暴露对待；边界是专用账号与吊销令牌。账号权限、签名密钥暴露和吊销方法见 [GitHub 接入](github.zh-CN.md)。

## bash 隔离

bubblewrap 沙箱要求 Linux、`bwrap` 和启动自检通过。`/healthz` 的 `sandbox` 字段显示是否已启用。

- `DWELL_SANDBOX=required` 在探测失败时拒绝启动，且不会恢复检查点；`NODE_ENV=production` 时默认采用此模式。
- `auto` 明确允许沙箱不可用时以路径检查和危险命令正则运行，是非生产环境默认值。
- `off` 关闭沙箱。

仓库镜像设置了 `NODE_ENV=production`，但没有安装 `bwrap`，因此运维配置隔离与预期模式前，默认启动会失败。沙箱未启用时，工作目录只是路径约定，bash 能 `cd` 出去。

启用后，bash 只能看到白名单挂载：

- `/usr`、`/etc`、Node 安装目录与 DNS 解析目录只读。
- 会话工作目录与 `/tmp` 可写；`/proc` 为沙箱私有实例。
- 状态、应用文件（包括 `.env`）、其他会话、`/home`、`/root` 和 Docker/systemd 套接字均不可见。

环境只含 `PATH`、`HOME=<工作目录>` 和指向 `/tmp/dwell-xdg` 的 `XDG_CONFIG_HOME`/`XDG_STATE_HOME`/`XDG_CACHE_HOME`，另加已配置的 GitHub 变量。各会话共享 `/tmp`；systemd 的 `PrivateTmp=yes` 将其与宿主 `/tmp` 隔开。

沙箱不隔离网络。面板的本机来源检查阻止 bash 直连；其他可代发请求的服务需通过网络策略限制。主机隔离、沙箱配置和服务器探针 [test/probe-bwrap.ts](../test/probe-bwrap.ts) 的用法见[部署](deployment.zh-CN.md)。

## 文件工具与上传

普通任务线的 `write` 与 `edit` 只能写会话工作目录和系统临时目录，`read` 禁读状态目录、应用目录、数据库和 `/proc`。Telegram 群成员独立任务线及其子代理的文件工具均限本人工作目录，包括读写与目录列表；其他任务线仍可读取未受保护的系统路径。固定 POSIX 辅助进程核对目录身份，并持有最终文件描述符进行字节读写；硬链接文件和路径变化会被拒绝。每次文件操作增加一次辅助进程启动开销。

Windows 不提供受保护的文件访问。此后端不支持 `rename`、`remove` 或 `watch`。shell 另按沙箱和命令规则处理。

附件使用固定写入器，绑定已注册的工作区和上传目录身份，以独占方式创建新文件，拒绝链接、已有目标与目录变化。上传文件仍可写。重复消息可能留下不同附件文件；输入提交仍按消息 ID 去重。Linux 使用现有 bash 沙箱，macOS 执行同样的目录检查但没有沙箱。Windows 拒绝附件上传，文本功能仍可用。媒体处理和文件投递限制见[使用指南](usage.zh-CN.md)。

## 状态保护与命令审批

状态文件放在代理可写域之外。`users.json`、`sessions.json`、`message-map.json` 和 `approvals.json` 由文件工具路径检查与 bash 正则双重拦截。bash 仍可用通配符、软链、重定向等变体绕过这些检查；沙箱未启用时，这些检查只能拖慢攻击，硬边界是部署隔离。

危险命令正则无法覆盖所有变体。命中危险模式的命令需审批；访问状态文件、`.env` 或 `/proc/*/environ`，以及使用 `sudo`，均直接拒绝。沙箱启用后仍保留正则作为纵深防御，用于确认命中命令的意图。执行预算与工作区归属见[代理运行机制](agent.zh-CN.md)，审批行为见[使用指南](usage.zh-CN.md)。

## 面板访问

面板没有内置登录。部署侧网络边界与以下请求检查共同保护它：

- POST 强制 `Content-Type: application/json`。
- 有 `Origin` 时，其主机名和端口必须与 `Host` 匹配；格式错误的 Origin 和 `Origin: null` 会被拒绝。
- `Host` 只接受 IP 字面量、内置的 `localhost` 名称，或 `DWELL_PANEL_HOST`/`DWELL_PANEL_URL` 配置的主机名。

这些检查防止跨站请求借操作者的浏览器访问内网面板（CSRF），也防止通过 DNS 重绑定读取 SSE。

本机来源（回环与本机任一接口地址）的请求，除 `/healthz` 外一律返回 403。bash 与面板同机；允许它调用面板，就可能让代理自批危险命令、添加管理员或读取所有会话。就绪状态、运行指标、静态页面和 SSE 都受同样的本机来源拒绝约束。

`DWELL_PANEL_ONLY=1` 关闭两个机器人连接，并允许本机访问面板，供开发使用。`DWELL_PANEL_TRUST_LOCAL=1` 允许本机访问，但不关闭机器人。同机反代或 `ssh -L` 隧道会让请求显示为本机来源，需要显式设置这项信任；开启后 bash 也能访问面板和审批 API。优先让浏览器从另一台机器连接。面板设置见[配置](configuration.zh-CN.md)，本地检查见[开发](development.zh-CN.md)，网络部署与验证见[部署](deployment.zh-CN.md)。
