# Agent 运行机制

[English](agent.md) | 简体中文 | [首页](../README.zh-CN.md)

日常操作见[使用指南](usage.zh-CN.md)，安装与监控见[部署与运维](deployment.zh-CN.md)。本文说明执行、验证与恢复的契约。

## 会话与恢复

飞书、Telegram 和 panel 经过路由与权限检查后进入 pi-durable 会话；模型与工具使用同一持久化任务运行时。会话文件位于工作目录，SQLite 与服务私有状态的目录约束见[配置](configuration.zh-CN.md)和[安全边界](security.zh-CN.md)。

Telegram 获准的原始输入先写入 SQLite 持久化 inbox，再推进轮询游标。4 个路由 worker 并行预处理，各路由内保持顺序；`/cancel` 同时取消该路由尚未处理的原始输入，包括正在下载或进行视觉分析的请求。预处理退出后释放路由；已经开始的上传写入可能完成，不会回滚删除。已取消输入不会提交模型或重试。重投保留原请求与控制目标，出站答案按实际的持久化答案 ID 去重。审批投递容量不足时，决定保留为待投递，稍后重试。旧待处理任务缺少可信操作者身份时会停止，需重新请求，服务不会借用当前发送者身份。发送响应丢失仍会使投递结果不确定，这些记录不保证出站消息或工具副作用恰好一次。

## 运行预算

每个会话 run 有独立、持久化的预算，默认普通生成请求准入 32 次、唯一工具准入 128 次、执行墙钟时间 15 分钟。准入按请求或工具边界的尝试计数，包含 durable 模型重试和被审批拦截的工具调用；schema 无效的调用不计，工具数也不等于物理执行次数。provider SDK 内部重试关闭（`maxRetries: 0`）。压缩上下文同样受执行期限约束，可在到期时取消，但不占用 32 次普通生成请求额度。

预算创建后冻结限额，重启后继续使用；执行阶段活跃时发生的停机时间保守计入。run 结束后的审批等待、定时任务等待不计入执行时间。运行中插话不重置预算，审批续跑沿用原预算；旧待审记录没有预算 ID 时，在首次续跑创建预算。后台子会话的初始 run 有自己的预算，结果送回父会话时，父会话 follow-up 使用新预算。达到上限就停止该 run 并报告原因，不会杀掉 `dwell.proc` 托管进程，其生命周期可超过 15 分钟。`/cancel`、停止后台子代理、停止托管进程仍各自作用于原有范围。

## 共享工作区

`dwell.task start` 默认 `mode: "read"`。只读任务可以在写入者工作时分析共享文件，但没有 shell、write/edit 或不安全工具权限；hook 中的违规调用也会被检查。需要执行命令或改文件时，在 start 时显式选 `mode: "write"`；模式在子会话生命周期内固定。可写 start 必须是该次模型回复中唯一的工具调用，混合批次会被拒绝。

可写子会话在整个 run 与审批等待期间持有持久化的工作区写租约。父会话交出当前 run 的写权限，即使子会话提前结束也不恢复；结果到达后，父会话可在新 run 中写入，编辑前应重读相关文件。竞争写入者、嵌套路径与同一工作区的别名都会检查。交接前先停止占用该工作区的托管进程。旧后台子会话没有访问角色时，恢复前迁移为只读。父子会话仍共享文件，这些协调规则不构成租户之间的安全隔离。

shell 与托管进程把 npm/npx 缓存放在系统临时目录，Linux 沙箱内为 `/tmp/dwell-xdg/npm-cache`，避免写入工作目录。项目明确生成的产物仍受任务的文件契约约束。

## 等待后台结果

父线需要后台结果时，单独调用 `dwell.task.wait`。宿主会结束当前 run，不再请求模型生成一句终答；已有的持久回报随后启动续跑。Telegram、飞书和 panel 会显示等待提示。显式等待前，父线仍可处理独立工作。等待不会停止子任务，`/cancel` 保留原有范围；`status` 只查看状态，不会交付排队中的回报。

等待的调用格式为 `{"name":"dwell.task.wait","arguments":{}}`。它是独立的安全重放工具，`dwell.task` 没有 `wait` 动作。启动和状态结果都会提供这个调用示例；误用 `action: "wait"` 时，会在执行前返回纠正指引。

## 工作记录

跨 run 的任务可用 `dwell.work` 将目标、验收标准、进度、阻塞项、证据 ID 与评审说明保存在 SQLite 中。模型应在实质工作前创建记录，在等待澄清等情况前保存进度，检查标准后请求 `ready_for_review`。证据 ID 必须对应这项工作任务树中的成功工具结果；工具成功本身不能证明用户验收。只有原工作创建者能通过模型工具修改记录，已验收记录不能再由该工具编辑。开始新目标后，后台子会话与托管进程回报仍归属创建时的工作。

每项工作冻结聚合上限：根会话与归属该工作的后台子会话共用 128 次生成准入、512 次工具准入，单 run 限额仍然有效。工作账本标记 `usage.scope: "generation_and_tools"`，不包含上下文压缩和视觉调用。`pricingKnown` 为 true 时费用按已记录用量估算，价格未知时为 `null`。

需要解除当前目标并开始另一项工作时，使用 [`/newgoal`](usage.zh-CN.md#命令)；该操作保留旧记录与聊天历史。每条会话最多保留 64 项工作记录，达到上限后可在任一 bot 使用 `/new`，或新建 panel 会话。旧记录仍可在原会话中查看。

## 验证与验收

### 声明最终产物

代码或文件工作在 `start` 时声明验证契约：`checks: [{name, command}]` 保存实际检查命令，`artifacts` 指定必须存在的工作区相对路径，严格输出任务可另设 `allowedChanges`。例如 `artifacts: ["job", "job/result.json"]` 配合 `allowedChanges: ["job/result.json"]`，会检查包含目录中的额外变动，并要求结果文件存在。目录递归检查，范围最多 1024 项、16 MiB 文件内容、64 层目录；应选择明确的小范围，避免扫描整个仓库或依赖树。

产物声明描述最终必须存在的状态。对于之后要删除的临时文件，应把清理后仍会存在的包含目录列入 `artifacts`、精确文件路径列入 `allowedChanges`，不要要求该临时文件在完成时仍然存在。如果整个 `job/disposable` 都会删除，目录范围应声明为 `job`。错误的产物范围不能通过 `revise` 修正。模型应保存阻塞并说明原因，操作者再用 `/newgoal` 声明正确目标，旧记录与聊天历史继续保留。`dwell.work` 会拒绝未知参数，避免把忽略了参数的请求显示为成功。

### 执行检查

`dwell.work verify` 经已有 bash 工具执行声明的检查，保留审批、预算和写租约约束。宿主回执记录成功退出码与最终文件的 SHA256 清单。`ready` 和操作者验收只复查哈希，不执行命令；文件变化或缺失就要求重新验证。中断的验证命令不会自动重放。没有契约的记录明确标为未验证，保留兼容的评审行为。回执证明命令结果及对应文件版本，检查本身仍需覆盖实际需求和目标运行时；普通聊天不强制建立工作记录。

检查失败时，工作失败记录会把受治理的 bash 结果中的诊断与 stdout/stderr 合并输出反馈给模型。诊断最多保留 2,000 字符，输出保留末尾 4,000 字符，并标明截断。审批拦截与超时会保留工具提供的原因；工具在超时后未返回的部分输出不会另行恢复。检查成功时不附加命令输出。

### 修订检查

声明的检查有误时，可用 `dwell.work` 的 `action: "revise"`、替换后的 `checks` 和非空 `reason` 修订当前工作的命令。目标、验收要求、原始文件 baseline、产物范围、允许修改的路径、归属和预算保持不变。修订历史保存旧检查、旧回执、旧尝试、操作者和原因；当前回执立即失效，必须重新验证。只有根会话中的原创建者能修订尚未验收的工作。历史最多保留 32 次修订，达到上限后拒绝继续修订，不丢弃旧记录；修订也不能重置已耗尽的预算。模型上下文只携带精简历史摘要，panel 工作 API 保留完整历史。

### 提交评审

验证成功会保留未解决的阻塞项。明确解决后通过 checkpoint 更新阻塞项，工作仍满足提交条件时，返回值才提供可直接使用的 `ready nextCall`；补充证据条目 ID 可以省略。`ready` 必须是单独的直接模型工具调用；成功后由宿主结束当前 run，通过 Telegram、飞书或 panel 显示待验收提示，不再请求模型。提示包含有长度限制的目标声明、产物范围、检查记录和代理评审说明，冻结在该次 ready 回执中；后续目标或检查修订不会改写历史提示。未声明契约的工作会明确提示未验证。这些提示都不代表操作者验收。

panel 只有在宿主将工具回执与实际答案、任务关联后，才显示待验收通知；模型文本不能自行产生这类通知。

### 记录验收

从 panel 会话菜单或待验收通知打开「工作记录与验收」，可查看当前与历史工作、验收标准、产物范围、检查记录、交付说明和验收记录。检查产物后确认验收；需要修改时，继续在任务线发送修改要求。

可信 panel API 通过 `GET /api/work?id=<conversationId>` 读取相同记录，通过 `POST /api/work/accept`，提交 JSON `{ "id": <conversationId>, "workId": "work:..." }` 记录验收。模型工具没有 accept 动作；这两个接口沿用 panel 的请求与网络准入策略。

操作者验收通过受保护的文件环境重读声明的产物，不会执行验证命令。

| `dwell.proc` | 在会话的沙箱与工作目录内托管后台进程。启动、状态和退出回报均提供任务 ID；stdout/stderr 由服务保存到私有日志。退出码与日志尾以 followUp 报回（`notify: false` 可关正常退出通知）；日志存储失败会停止进程并报告，即使通知已关闭。`stop` 杀进程树；`/cancel` 与清空上下文不影响。服务重启后报告进程中断，不自动重跑命令。每会话上限 5 个、全局 10 个 | 危险启动命令需审批（同 bash） |
| `dwell.proc.logs` | 按 `taskId` 读取当前任务线的进程日志。默认末尾 50 行，最多 200 行、64 KiB。单文件达到 50 MiB 后截断并写标记；已结束日志保留 7 天。用此工具代替 `read` 或 `tail` | 免审 |
